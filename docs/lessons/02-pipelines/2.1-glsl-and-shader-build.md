## 1. Concepts

### 1.1 What a shader is

A shader is a **small program that runs on the GPU, once per item, thousands of times in
parallel**. In this phase you meet two kinds:

| Shader | Runs once per | Its job | Required output |
|---|---|---|---|
| **Vertex shader** (`.vert`) | **corner** (vertex) | Decide *where* the corner is on screen | `gl_Position` |
| **Fragment shader** (`.frag`) | **pixel** the triangle covers | Decide the pixel's *color* | `layout(location = 0) out vec4` |

Between the two, the GPU's fixed hardware (the **rasterizer**) works out which pixels each
triangle covers and **interpolates** the vertex shader's outputs across the triangle. That's
why a triangle with a red, a green and a blue corner comes out as a smooth rainbow (lesson 2.2).

```
 3 corners ──► vertex shader ×3 ──► rasterizer ──► fragment shader ×(every covered pixel) ──► image
               "where?"             "which pixels?    "what color?"
                                     blend the
                                     outputs"
```

Tech-art link: an Unreal material's **World Position Offset** is vertex-shader work. Almost
everything else in the material graph (Base Color, Roughness, ...) ends up in the fragment
(pixel) shader.

### 1.2 GLSL for a C++ programmer

GLSL looks like C, without pointers, headers, classes, recursion or the standard library, and
with **vectors and matrices built in**.

```glsl
#version 450                                  // always the first line

layout(location = 0) in  vec3 inPosition;     // input  (from a vertex buffer, or from the previous stage)
layout(location = 0) out vec4 outColor;       // output (to the next stage, or to the image)

const float PI = 3.14159265;                  // constants are fine

float luminance(vec3 c)                       // functions are fine (no recursion)
{
    return dot(c, vec3(0.2126, 0.7152, 0.0722));
}

void main()                                   // entry point, no arguments, no return value
{
    outColor = vec4(vec3(luminance(inPosition)), 1.0);
}
```

**Types you'll use constantly**

| GLSL | Meaning | HLSL / Unreal equivalent |
|---|---|---|
| `float`, `int`, `uint`, `bool` | scalars | same |
| `vec2`, `vec3`, `vec4` | 2/3/4 floats | `float2`, `float3`, `float4` |
| `ivec2`, `uvec3`, ... | integer vectors | `int2`, `uint3` |
| `mat3`, `mat4` | 3×3, 4×4 float matrices (**column-major**) | `float3x3`, `float4x4` |

**Constructors**: flexible, and they "spill" components in order:

```glsl
vec3 a = vec3(1.0);              // (1, 1, 1): a single value fills every component
vec4 b = vec4(a, 0.5);           // (1, 1, 1, 0.5)
vec4 c = vec4(0.2, a.xy, 1.0);   // (0.2, 1, 1, 1)
```

**Swizzling**: pick or reorder components by name. `xyzw`, `rgba` and `stpq` are the same
four slots under different names; use whichever reads best:

```glsl
vec4 color = vec4(0.9, 0.5, 0.1, 1.0);
vec3 rgb   = color.rgb;     // (0.9, 0.5, 0.1)
vec3 bgr   = color.bgr;     // (0.1, 0.5, 0.9): reordered
vec2 rr    = color.rr;      // (0.9, 0.9): repeated
color.a    = 0.5;           // write a single component
```

**Write float literals with a dot**: `1.0`, not `1`. GLSL converts some integer literals for
you, but not everywhere, and HLSL behaves differently. `1.0` always works and makes the
intent obvious.

**Operators work per component**: `vec3 * vec3` multiplies x with x, y with y, z with z.
`vec3 * float` scales all three. (The exception: `mat4 * vec4` is a real matrix multiply,
in Phase 3.)

### 1.3 The built-in functions you'll use every day

These are the ones that show up in nearly every shader and every material graph:

| GLSL | Does | Unreal material node / HLSL |
|---|---|---|
| `mix(a, b, t)` | `a + (b − a)·t`, a linear blend | **Lerp** / `lerp` |
| `clamp(x, lo, hi)` | Keep `x` in `[lo, hi]` | **Clamp** |
| `clamp(x, 0.0, 1.0)` | Keep in 0..1 | **Saturate** / `saturate` |
| `step(edge, x)` | `0` if `x < edge`, else `1`: a hard cut | `step` |
| `smoothstep(e0, e1, x)` | Smooth 0→1 between `e0` and `e1`: a soft cut | **SmoothStep** |
| `fract(x)` | The fractional part: makes things **repeat** | **Frac** / `frac` |
| `mod(x, y)` | Remainder (always positive for positive `y`) | `fmod` *(differs for negative x!)* |
| `sin`, `cos` | Waves, rotations | **Sine**, **Cosine** (Unreal's take 0..1 periods) |
| `abs`, `min`, `max`, `pow`, `sqrt` | As in C++ | same |
| `length(v)`, `distance(a, b)` | Vector length | **Length**, **Distance** |
| `dot(a, b)` | How aligned two directions are | **Dot** |
| `normalize(v)` | Same direction, length 1 | **Normalize** |

Learn `mix`, `fract`, `step`/`smoothstep` and `dot` really well. Most procedural patterns are
combinations of these four.

### 1.4 Built-in variables

| Name | Stage | Meaning |
|---|---|---|
| `gl_Position` | vertex, **output** | Where the corner goes, in **clip space** (below) |
| `gl_VertexIndex` | vertex, input | Which vertex this run is: 0, 1, 2, ... (in OpenGL GLSL it's called `gl_VertexID`) |
| `gl_FragCoord` | fragment, input | This pixel's position in **pixels** (`.xy`), e.g. (812.5, 340.5) |

### 1.5 Where is "on screen"? Vulkan clip space

For now, `gl_Position` takes coordinates in **clip space** directly (no camera until Phase 3):

```
        (-1,-1) ─────────────── (1,-1)        x: -1 = left edge,  +1 = right edge
           │                       │          y: -1 = TOP edge,   +1 = bottom edge   ← Vulkan!
           │         (0,0)         │          z:  0 = near, 1 = far (depth, lesson 3.3)
           │                       │          w:  1.0 for now (perspective, lesson 3.1)
        (-1, 1) ─────────────── (1, 1)
```

**Vulkan's y axis points down**, unlike OpenGL. Shadertoy examples and OpenGL tutorials will
look upside down if you copy their numbers directly. Lesson 3.1 fixes this for the 3D camera
with one line (`proj[1][1] *= -1`).

### 1.6 From GLSL text to the GPU: SPIR-V and glslc

GPUs don't read GLSL text. Vulkan wants **SPIR-V**: a compact binary bytecode, the shader
equivalent of an `.obj` file.

```
triangle.vert ──glslc──► triangle.vert.spv ──(app reads file)──► VkShaderModule ──► pipeline (2.2)
 (you write)    (build)   (in out/build/.../shaders/)              (lesson 2.1)
```

- **`glslc`** is the shader compiler that ships with the Vulkan SDK (`D:\Vulkan\Bin\glslc.exe`).
- Compiling **at build time** means a GLSL syntax error stops the build with a file name and
  line number, just like a C++ error. You find it in the Output window, not at runtime.
- Phase 7 adds **runtime** compilation, so you can edit a shader while the app runs and see the
  result instantly (hot reload). Build-time compilation is the simple first step.

Tech-art link: this is the same split as Unreal's **shader compilation**. HLSL text is compiled
to bytecode (DXIL/SPIR-V) before the GPU can run it. The "Compiling Shaders (3,452)" counter
in the editor is this step, done for thousands of material permutations.

### Step 1 — `CMakeLists.txt`: compile shaders on every build

Replace your whole `CMakeLists.txt` with this. Compared to yours, it **removes the file list
Visual Studio kept appending to `add_executable`** (the glob already finds everything) and
**adds the shader section**:

```cmake
cmake_minimum_required(VERSION 3.25)
project(VulkanShaderPlayground VERSION 0.1.0 LANGUAGES CXX)

# --- Language ---------------------------------------------------------------
set(CMAKE_CXX_STANDARD 20)            # designated initializers, std::format, concepts
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

# --- Dependencies -----------------------------------------------------------
find_package(Vulkan REQUIRED COMPONENTS glslc)          # from the SDK (VULKAN_SDK)
find_package(glfw3 CONFIG REQUIRED)                     # from vcpkg
find_package(glm CONFIG REQUIRED)                       # from vcpkg
find_package(VulkanMemoryAllocator CONFIG REQUIRED)     # from vcpkg

# --- Executable -------------------------------------------------------------
# GLOB is convenient for a learning project: new files are picked up on the next
# build. (Big projects list files explicitly for reproducibility.)
file(GLOB_RECURSE VSP_SOURCES CONFIGURE_DEPENDS src/*.cpp src/*.h)
add_executable(VulkanShaderPlayground ${VSP_SOURCES})

target_include_directories(VulkanShaderPlayground PRIVATE src)

target_link_libraries(VulkanShaderPlayground PRIVATE
    Vulkan::Vulkan
    glfw
    glm::glm
    GPUOpen::VulkanMemoryAllocator)

# --- Shaders: GLSL -> SPIR-V at build time (lesson 2.1) ----------------------
# Every .vert/.frag/.comp under shaders/ becomes <build>/shaders/<name>.spv,
# e.g. shaders/triangle.vert -> out/build/x64-debug/shaders/triangle.vert.spv
file(GLOB_RECURSE VSP_SHADER_SOURCES CONFIGURE_DEPENDS
    ${CMAKE_SOURCE_DIR}/shaders/*.vert
    ${CMAKE_SOURCE_DIR}/shaders/*.frag
    ${CMAKE_SOURCE_DIR}/shaders/*.comp)

set(VSP_SHADER_BIN_DIR ${CMAKE_BINARY_DIR}/shaders)
set(VSP_SPIRV_FILES "")

foreach(SHADER ${VSP_SHADER_SOURCES})
    get_filename_component(SHADER_NAME ${SHADER} NAME)         # triangle.vert
    set(SPIRV ${VSP_SHADER_BIN_DIR}/${SHADER_NAME}.spv)         # .../triangle.vert.spv
    add_custom_command(
        OUTPUT  ${SPIRV}
        COMMAND ${CMAKE_COMMAND} -E make_directory ${VSP_SHADER_BIN_DIR}
        COMMAND ${Vulkan_GLSLC_EXECUTABLE} --target-env=vulkan1.3 -g -o ${SPIRV} ${SHADER}
        DEPENDS ${SHADER}
        COMMENT "glslc ${SHADER_NAME}"
        VERBATIM)
    list(APPEND VSP_SPIRV_FILES ${SPIRV})
endforeach()

add_custom_target(VspShaders DEPENDS ${VSP_SPIRV_FILES} SOURCES ${VSP_SHADER_SOURCES})
add_dependencies(VulkanShaderPlayground VspShaders)   # shaders are (re)compiled before the exe

target_compile_definitions(VulkanShaderPlayground PRIVATE
    GLM_FORCE_DEPTH_ZERO_TO_ONE    # Vulkan depth range is [0,1], not OpenGL's [-1,1] (lesson 3.1)
    GLM_FORCE_RADIANS
    NOMINMAX                       # stop <windows.h> from defining min/max macros
    WIN32_LEAN_AND_MEAN
    VSP_ASSETS_DIR="${CMAKE_SOURCE_DIR}/assets"
    VSP_SHADERS_DIR="${CMAKE_SOURCE_DIR}/shaders"
    VSP_SHADER_BIN_DIR="${VSP_SHADER_BIN_DIR}")   # where the compiled .spv files are

if(MSVC)
    target_compile_options(VulkanShaderPlayground PRIVATE /W4 /permissive- /utf-8)
endif()
```

What the shader section does, line by line:

| Line | Meaning |
|---|---|
| `file(GLOB_RECURSE VSP_SHADER_SOURCES ...)` | Find every shader under `shaders/`, like the C++ glob |
| `foreach(SHADER ...)` | For each shader file... |
| `add_custom_command(OUTPUT ... COMMAND glslc ...)` | ...define a build rule: "to make `X.spv`, run glslc on `X`". `DEPENDS` means it only re-runs when that shader changes |
| `--target-env=vulkan1.3` | Generate SPIR-V for Vulkan 1.3 |
| `-g` | Keep debug info, so RenderDoc can show your GLSL source instead of bytecode |
| `add_custom_target(VspShaders ...)` | A target that "builds" all the `.spv` files. `SOURCES` makes the shaders show up in VS's CMake Targets view |
| `add_dependencies(...)` | Build the shaders **before** the exe, on every build |
| `VSP_SHADER_BIN_DIR` | Tells the C++ code where to find the `.spv` files |

**After saving:** Project → **Configure Cache** (or just build). When Visual Studio offers to add
files to CMakeLists from now on, **say no**. The globs handle it.

### Step 2 — Write your first shaders (exercise)

Create `shaders/triangle.vert` and `shaders/triangle.frag`. There's **no vertex buffer yet**
(that's 2.3): the three corners are **hard-coded inside the vertex shader** and picked with
`gl_VertexIndex`.

**`triangle.vert`** must:
- start with `#version 450`,
- hold a `const` array of 3 `vec2` positions: top center, bottom right and bottom left,
  inside the `-0.5 .. 0.5` range (remember: **y = -0.5 is above** y = 0.5),
- hold a `const` array of 3 `vec3` colors: red, green, blue,
- declare one output: `layout(location = 0) out vec3 vColor;`,
- in `main()`: set `gl_Position` from the position array (`z = 0.0`, `w = 1.0`) and `vColor`
  from the color array, both indexed with `gl_VertexIndex`.

**`triangle.frag`** must:
- declare the matching input: `layout(location = 0) in vec3 vColor;` (**same location** as the output),
- declare the output: `layout(location = 0) out vec4 outColor;`,
- in `main()`: write `vColor` with alpha `1.0`.

<details><summary>Hint: GLSL array syntax</summary>

```glsl
const vec2 positions[3] = vec2[](
    vec2(0.0, 0.0),
    vec2(1.0, 0.0),
    vec2(0.0, 1.0)
);
// use: positions[gl_VertexIndex]
```
</details>

<details><summary>Hint: building gl_Position from a vec2</summary>

`gl_Position` is a `vec4`. Use the spilling constructor: `vec4(myVec2, 0.0, 1.0)`.
</details>

<details><summary>Solution: triangle.vert</summary>

```glsl
#version 450

// No vertex buffer yet: the three corners are hard-coded and picked by gl_VertexIndex (0, 1, 2).
// Vulkan clip space: x -1 (left) .. +1 (right), y -1 (TOP) .. +1 (bottom).
const vec2 positions[3] = vec2[](
    vec2( 0.0, -0.5),   // top
    vec2( 0.5,  0.5),   // bottom right
    vec2(-0.5,  0.5)    // bottom left
);

const vec3 colors[3] = vec3[](
    vec3(1.0, 0.0, 0.0),   // red
    vec3(0.0, 1.0, 0.0),   // green
    vec3(0.0, 0.0, 1.0)    // blue
);

layout(location = 0) out vec3 vColor;   // handed to the fragment shader, interpolated per pixel

void main()
{
    gl_Position = vec4(positions[gl_VertexIndex], 0.0, 1.0);
    vColor      = colors[gl_VertexIndex];
}
```
</details>

<details><summary>Solution: triangle.frag</summary>

```glsl
#version 450

layout(location = 0) in  vec3 vColor;     // same location as the vertex shader's output
layout(location = 0) out vec4 outColor;   // location 0 = the first color attachment (the swapchain image)

void main()
{
    outColor = vec4(vColor, 1.0);
}
```
</details>

Build. In the Output window you should see:

```
[1/14] glslc triangle.vert
[2/14] glslc triangle.frag
```

and the files `out/build/x64-debug/shaders/triangle.vert.spv` and `triangle.frag.spv` should exist.

### Step 3 — `vk/ShaderModule.h/.cpp`: load SPIR-V

A `VkShaderModule` is just "this SPIR-V, handed to the driver". You only need it while
building a pipeline (2.2), and you destroy it right afterwards.

**`src/vk/ShaderModule.h`**

```cpp
#pragma once

#include <vulkan/vulkan.h>

#include <cstdint>
#include <string>
#include <vector>

namespace vsp::vkutil {

	// Read a compiled .spv file. SPIR-V is a stream of 32-bit words.
	std::vector<uint32_t> readSpirv(const std::string& path);

	// Load a .spv file and wrap it in a VkShaderModule.
	// The module is only needed while building a pipeline: destroy it right after.
	VkShaderModule loadShaderModule(VkDevice device, const std::string& path);

	// Full path of a compiled shader, e.g. shaderPath("triangle.vert") -> ".../shaders/triangle.vert.spv"
	std::string shaderPath(const std::string& name);

}
```

**`src/vk/ShaderModule.cpp`**

```cpp
#include "vk/ShaderModule.h"
#include "vk/VkCheck.h"
#include "core/Log.h"

#include <fstream>
#include <stdexcept>

namespace vsp::vkutil {

	std::vector<uint32_t> readSpirv(const std::string& path)
	{
		std::ifstream file(path, std::ios::binary | std::ios::ate);   // ate: start at the end to get the size
		if (!file)
			throw std::runtime_error("Shader not found: " + path + " (did the build run glslc?)");

		const std::streamsize bytes = file.tellg();
		if (bytes <= 0 || bytes % 4 != 0)
			throw std::runtime_error("Not a valid SPIR-V file: " + path);

		std::vector<uint32_t> words(static_cast<size_t>(bytes) / 4);
		file.seekg(0);
		file.read(reinterpret_cast<char*>(words.data()), bytes);
		return words;
	}

	VkShaderModule loadShaderModule(VkDevice device, const std::string& path)
	{
		const std::vector<uint32_t> code = readSpirv(path);

		VkShaderModuleCreateInfo info{ VK_STRUCTURE_TYPE_SHADER_MODULE_CREATE_INFO };
		info.codeSize = code.size() * sizeof(uint32_t);   // in BYTES, not words
		info.pCode    = code.data();

		VkShaderModule module = VK_NULL_HANDLE;
		VK_CHECK(vkCreateShaderModule(device, &info, nullptr, &module));
		log::info("Loaded shader {} ({} bytes)", path, info.codeSize);
		return module;
	}

	std::string shaderPath(const std::string& name)
	{
		return std::string(VSP_SHADER_BIN_DIR) + "/" + name + ".spv";
	}

}
```

Why `std::vector<uint32_t>` and not `std::vector<char>`? `pCode` is a `const uint32_t*`, and
Vulkan requires that pointer to be 4-byte aligned. A `uint32_t` vector guarantees that.

Nothing calls `loadShaderModule` yet. That happens in 2.2, when the pipeline needs it.

## 4. Common pitfalls

| Symptom | Cause / fix |
|---|---|
| No `glslc` lines in the build output | CMake hasn't re-run since you added the shaders. Project → Configure Cache |
| `Vulkan_GLSLC_EXECUTABLE-NOTFOUND` | The SDK's `Bin` folder isn't found. Check that `VULKAN_SDK` = `D:\Vulkan` and restart VS |
| `Shader not found: ...spv` at runtime | Build didn't compile it, or you passed the wrong name. `shaderPath("triangle.vert")`, not `"triangle"` or `"triangle.vert.spv"` |
| Interface mismatch warnings (2.2) | The vertex shader's `out` and the fragment shader's `in` must use the **same location** and type |
| A shader copied from Shadertoy/OpenGL is upside down | Vulkan's y axis points down (§1.5) |

## 5. Check your understanding

1. A triangle covers 10,000 pixels. How many times does the vertex shader run? The fragment shader?
2. What does `color.bgr` return for `color = vec4(0.1, 0.2, 0.3, 1.0)`?
3. Where is the point `(0.0, -0.9)` on screen in Vulkan clip space? And in OpenGL?
4. Why does the app load `.spv` files and not `.vert` files?
5. Which GLSL function would you use to make a pattern repeat 8 times across a surface?

<details><summary>Answers</summary>

1. Vertex shader: 3 times (once per corner). Fragment shader: about 10,000 times (once per covered pixel).
2. `vec3(0.3, 0.2, 0.1)`.
3. Vulkan: near the **top** center. OpenGL: near the bottom center (y points up there).
4. The GPU driver only accepts SPIR-V bytecode. GLSL is compiled to SPIR-V by `glslc` during the build.
5. `fract(uv * 8.0)`: multiply to get 0..8, then `fract` wraps it back to 0..1 eight times.
</details>
